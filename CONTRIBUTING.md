# Contributing to GSLHub

Thank you for your interest in contributing to GSLHub.

GSLHub combines open-source software engineering with applied research in Generative Search, GEO, AI evaluation and reproducible research. Contributions should therefore preserve both technical quality and research traceability.

## Ways to contribute

You can contribute through bug reports, documentation improvements, reproducibility fixes, accessibility improvements, tests, research tooling, benchmark design, data-quality improvements and well-scoped feature proposals.

For significant changes, please open an issue or discussion first so the scope, research impact and implementation approach can be agreed before substantial work begins.

## Development expectations

- Keep changes focused and explain the problem being solved.
- Do not commit credentials, API keys, private datasets, personal data or production secrets.
- Preserve research provenance and existing audit/reproducibility controls.
- Do not alter validated research records, metric definitions or scientific lifecycle rules without explicitly documenting the methodological impact.
- Add or update tests and documentation when behavior changes.
- Keep TypeScript, lint and production-build checks passing before requesting review.
- Prefer clear branch names such as `feat/...`, `fix/...`, `docs/...` or `research/...`.
- Use descriptive commits and pull-request summaries that explain both the change and why it is needed.

## Research integrity

Research-related contributions must distinguish clearly between test/development data and evidence intended for scientific analysis.

Synthetic examples, mock outputs and development fixtures must be identifiable as such. Do not present generated, inferred or reconstructed information as observed experimental evidence.

If a contribution changes methodology, evaluation criteria, benchmark behavior, evidence relationships or reproducibility controls, document that impact explicitly in the pull request.

## Licensing

Unless a repository states otherwise, contributions to GSLHub software repositories are submitted under the license of that repository. The core GSLHub platform is licensed under **GNU AGPL-3.0**.

By submitting a contribution, you confirm that you have the right to provide it under the applicable project license.

Datasets, publications, brand assets and third-party materials may use separate licenses or usage terms.

## Pull requests

A good pull request should include a concise summary, the motivation for the change, relevant validation or test results, and any impact on research methodology, data structures, deployment or compatibility.

Small, reviewable pull requests are preferred over large unrelated changes.

## Contact

For contribution questions that should not be handled in a public issue, contact **research@gslhub.com**.
